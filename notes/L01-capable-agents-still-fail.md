# L01. Сильна модель — ще не гарантія надійного виконання

## Головна думка
Коли агент провалюється — **спочатку перевіряй harness, потім модель.**
Harness = усе, що не ваги моделі: інструкції, інструменти, середовище, стан, верифікація.

## 5 шарів, куди відносити кожен збій
1. **Специфікація задачі** — розмиті вимоги → агент вгадує
2. **Контекст** — неявні конвенції ніде не записані → агент їх не бачить
3. **Середовище** — зламаний dev-сетап → контекст іде на `npm install`
4. **Верифікація** — немає тестів/лінтера → «готово», бо «виглядає ок»
5. **Стан між сесіями** — кожна сесія з нуля

## Терміни
- **Verification Gap** — різниця між «агент каже готово» і «реально працює»
- **Definition of Done** — перевірні командами умови завершення (тести, typecheck, lint)
- **Diagnostic Loop** — запуск → збій → який шар? → виправити шар → запуск знову
- **Context anxiety** — агент поспішає завершити, коли контекст закінчується

## Практичний мінімум
- `AGENTS.md` / `CLAUDE.md` у корені: стек, конвенції, команди перевірки
- Явний Definition of Done на кожну задачу
- Простий журнал збоїв: задача → успіх/збій → шар
